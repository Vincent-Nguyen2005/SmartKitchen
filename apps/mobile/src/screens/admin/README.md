# Admin Screens

Owner: Huy. Responsibility: administration and operational management screens (#61, backed by #48/#49/#58/#59).

## Access

- The "Quản trị" tab is rendered only when `useSession().user.role === "ADMIN"` (see `App.tsx`). `AdminHome` repeats the check and shows "Không có quyền truy cập" otherwise.
- ADMIN accounts see **only** the "Quản trị" tab (SCRUM-283); all other tabs are hidden for them, and non-admins never see it.
- For ADMIN accounts `App.tsx` also hides the green "SmartKitchen" header; logout is the icon at the right end of the tab row (non-admins keep the header with "Đăng xuất").
- This is a UI guard only. The real check is on the server: the gateway sets `x-user-role` from the verified access token and admin-service requires `ADMIN` on every admin endpoint.

All screens use the shared client and UI from `../notifications/` (`gatewayApi.ts`, `useGatewayApi.ts`, `ui.tsx`) and the tokens/icons from `../../theme/`: loading / empty / error-with-retry states with an icon, accessible labels, `useWindowDimensions` layouts (1 column on phones, 2–3 on tablets/landscape).

Charts (`charts/`): `BarChart` and `LineChart` (react-native-svg, `chartColors` tokens, no chart library). Not used by any screen; kept for reuse.

Icons are Lucide (`lucide-react-native`, named imports) rendered through `AppIcon` / `IconButton`. Section tabs: LayoutDashboard (Tổng quan), Carrot (Nguyên liệu), CookingPot (Món ăn), BadgePercent (Khuyến mãi), Truck (Giao hàng); LogOut (Đăng xuất). Report and service statuses are shown as icon + text badges, never colour alone. Icon-only controls (report detail back button, ingredient form close button) have an `accessibilityLabel` and a 44 × 44 touch target.

### Ẩm thực (Món ăn)

The Món ăn form has an "Ẩm thực" dropdown next to "Loại món": Việt Nam (default), Âu Mỹ, Châu Á khác. It is sent as `cuisine`. Menus include at most 1 non-Vietnamese dish per meal and 2 per day.

### Safe delete (Nguyên liệu and Món ăn)

`safeDelete.ts`: the edit form of an existing ingredient or dish has "Ẩn" (hide, shown while visible) and "Xóa" (danger colour).
- "Xóa" asks "Xóa vĩnh viễn <tên>? Không thể hoàn tác." in the app `ConfirmDialog` (red confirm button), then calls `DELETE /api/admin/ingredients/:id` or `DELETE /api/recipes/:id`.
- On 409 IN_USE nothing is deleted: "Món này đang được dùng nên không xóa được. Bạn có thể ẩn nó." ("Nguyên liệu này …" for ingredients) plus the server's reasons, with "Ẩn" / "Đóng". For an item that is already hidden the message is shown in the form instead.
- After delete or hide the form closes and the list reloads on the same page (or the last page if that one is now empty).

## Manual test steps

Preparation: stack running, signed in as a user whose role is `ADMIN` in auth_db (and a normal user for steps 1–2).

1. **Role gating:** as a normal user the admin tab is not visible. Promote the account to ADMIN and sign in again → only the "Quản trị" tab is shown (Kho, Đi chợ, Thực đơn, … are hidden). Sign out and back in as a normal user → the normal tabs return.
2. **Server enforcement:** with a normal user's token, `GET /api/admin/reports` returns 403 (also covered by `pnpm test:e2e-smoke`; the endpoints stay, the app has no Báo cáo tab).
3. **Recipe steps:** in Món ăn › Sửa, each step shows only its own ingredients as tags ("Tôm ✕"); "+ Thêm nguyên liệu" opens a searchable list of the recipe's other ingredients. Saving keeps the same step data as before.
4. **Report conflict:** open the same report on two devices, resolve on one, then try on the other → conflict message.
5. **Service problems:** the health monitor still records service status (`SystemHealthScreen.tsx` is kept, not shown); Tổng quan no longer shows it.
6. **Ingredients:** add "Cà chua" with an image link (e.g. a public https .jpg) and 20 → the preview shows the image, the list row shows the thumbnail and "Đang khuyến mãi 20%"; as a normal user, Thông báo > Khuyến mãi lists "Cà chua giảm 20%" with the image and "Giảm 20%"; tap it → detail → "Mua" adds it to the family shopping list. Clear the % (or hide the ingredient) → the promotion disappears for users. A broken image link shows the placeholder and "Không tải được ảnh, kiểm tra lại link"; `http://` or `https://localhost/...` links are rejected. Stop notification-service and save with a % → the ingredient is saved and the retry message appears. Search `ca chua` finds "Cà chua". Create a duplicate name → "Tên nguyên liệu đã tồn tại." Hide an ingredient with the switch (top row of its card) → it stays in the list, dimmed. With more than 10 ingredients the pagination bar appears: "← Trước" is disabled on page 1, "Sau →" on the last page; on page 7 of 20 the numbers are 5–9. Typing a search goes back to page 1. Món ăn uses the same header and card row; its editor no longer shows "Theo người" (stored values are saved unchanged) or the step timer hint.
7. **Weights:** the "Trọng số" tab is hidden until a service consumes the weights; nothing to test in the app.
8. **Responsive:** on a tablet (width ≥ 720 and height ≥ 500) Health, ingredient and weight cards use 2–3 columns on wide screens and a lone last card keeps the column width. Native builds are portrait-locked by `app.config.ts`, so check landscape on web or a tablet.
9. **Errors:** stop admin-service → each screen shows the error state with "Thử lại".
10. **Safe delete:** edit an unused ingredient (or a dish never put in a menu) → "Xóa" → confirm → it disappears and the page stays. Edit an ingredient that is in a shopping list (or a dish in a saved menu) → "Xóa" → "đang được dùng" dialog with the reason → "Ẩn" hides it.
10. **Directory:** "Tổng quan" shows the user / family totals and up to 5 recent rows each. "Xem tất cả →" under families → Gia đình; tap a family → detail; back → Gia đình; back → dashboard. "Xem tất cả" → Người dùng; type part of a name or email → the list filters; pull down → it reloads. Back. Tap a family → its detail with members; back (or Android back) returns to the dashboard.
11. **Overview:** open "Tổng quan": three cards (users, families, new users in 7 days), labels never cut, same height; then the recent users and families.
12. **Statistics states:** stop admin-service → one error with "Thử lại"; if only one request fails, only its cards show "Không tải được".
13. **Statistics accessibility:** with TalkBack / VoiceOver each card reads its label and value; tappable cards are buttons with a hint.
