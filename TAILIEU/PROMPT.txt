TECHNICAL REQUIREMENTS:

1. MONOREPO ARCHITECTURE (pnpm + Turborepo):
   - Configure `pnpm-workspace.yaml` and `turbo.json`.
   - Root `package.json` scripts: `dev`, `build`, `lint`, and `test:health`.

2. SERVICE SCAFFOLDING (Express + TypeScript):
   - Scaffold `apps/gateway` (Port 4000) and all 11 services in `services/*`.
   - Use `node:20-alpine` as the base image for ALL Dockerfiles (do not mix Node versions across services).
   - Each service/app MUST contain:
     * Minimal `package.json` and `tsconfig.json`.
     * Entry point (`src/index.ts`) running Express server.
     * Route `GET /health` returning JSON: `{ status: "OK", service: "<service-name>", timestamp: ISOString }`.
     * A `.env.example` file declaring `PORT` and `DATABASE_URL`.
     * Multi-stage `Dockerfile` based on `node:20-alpine`.

3. DOCKER COMPOSE & STRICT DATABASE-PER-SERVICE:
   - `docker-compose.yml` MUST orchestrate 11 separate PostgreSQL container instances (one isolated database container per microservice, no shared database).
   - Configure healthchecks using `wget` (native to alpine images):
     `test: ["CMD-SHELL", "wget --no-verbose --tries=1 --spider http://localhost:<PORT>/health || exit 1"]`
   - Each service container MUST declare `depends_on` on its corresponding database container with `condition: service_healthy`, so the service only starts after its own database has passed its healthcheck (prevents Prisma connection-refused errors on first boot). Apply the same `depends_on: condition: service_healthy` pattern for `gateway` depending on all 11 services being healthy.

4. FUNCTIONAL TESTING & VERIFICATION SUITE:
   - Create `scripts/test-health.sh` (executable bash script, for Git Bash / WSL / macOS / Linux users) that:
     * Loops through ports 4000 to 4011.
     * Sends a `curl` request to `http://localhost:<PORT>/health`.
     * Validates that HTTP Status Code is `200` and response body contains `"status":"OK"`.
     * Displays a colored PASS/FAIL checklist in the terminal with a summary count (e.g., "12/12 Services Operational").
   - Also create `scripts/test-health.ps1`, a PowerShell equivalent of the same script (using `Invoke-WebRequest` or `Invoke-RestMethod`), producing the same PASS/FAIL checklist and summary count, for team members running native Windows PowerShell/cmd without Git Bash or WSL installed.
   - Update root `README.md` to include a dedicated **"Functional Verification Steps"** section with commands:
     1. How to run local type check & build (`pnpm build`).
     2. How to spin up Docker environment (`docker-compose up -d --build`).
     3. How to execute automated health test — both variants: `pnpm test:health` / `./scripts/test-health.sh` (Git Bash/WSL/macOS/Linux) AND `./scripts/test-health.ps1` (Windows PowerShell).
     4. How to test PostgreSQL connectivity for each database container (`docker exec -it ... psql`).
